# 多选全选/反选设计

## 背景

活动武将扩展中的多种技能允许玩家任选多张牌，但部分选择事件没有启用 noname 原生的全选能力。例如多个版本的“破军”在选择要扣置的牌时，只创建了多选事件，没有传入 `allowChooseAll`，因此即使本体开启了“全选按钮”配置也不会显示按钮。

noname 本体采用按事件显式启用的方式：事件设置 `allowChooseAll` 后，本地玩家在选择上限大于一时可看到“全选”按钮；已有选择时按钮切换为“反选”。本体同时负责配置开关、复杂选择保护、界面刷新和联机边界。

## 目标

- 为扩展内适合批量操作的多选事件启用 noname 原生全选/反选。
- 覆盖各种“破军”以及其他语义相同的安全多选场景，不绑定具体武将或技能名。
- 保持按钮样式、交互、配置和联机行为与 noname 本体一致。
- 不改变技能结算、AI、可选牌范围或选择上下限。

## 非目标

- 不复制或改写 noname 的全选按钮实现。
- 不强制开启玩家本体中的 `choose_all_button` 配置。
- 不给依赖组合合法性的复杂选择启用全选。
- 不调整技能平衡、描述或 AI 选牌逻辑。

## 方案

审计扩展中的多选调用，在符合条件的事件参数中加入 `allowChooseAll`，沿用本体的事件解析和 UI 注入机制。

适用场景包括：

- 从自己或其他角色区域任选一至多张牌。
- 任意张盖牌、交牌、弃牌、获得牌或重铸。
- 固定选择多张牌，且任意满足过滤条件的组合都合法。
- “至多 X 张”场景，包括多个版本的“破军”。

排除场景包括：

- 可选性依赖已选牌点数和、花色、牌名、类别或其他组合约束。
- 一次选择同时承担分组、排序、交换或分配职责。
- 事件使用 `complexCard` 或 `complexSelect`。
- 仅能选择一张牌。

如果调用链支持字符串参数，则直接传入 `"allowChooseAll"`；如果调用采用对象或链式配置，则设置 `allowChooseAll: true` 或 `.set("allowChooseAll", true)`。优先遵循相邻代码的既有写法。

## 交互流程

1. 技能创建多选事件并显式启用 `allowChooseAll`。
2. noname 本体检查当前是否为本地玩家、配置是否开启、选择上限是否大于一，以及事件是否为复杂选择。
3. 条件满足时，本体显示“全选”按钮。
4. 玩家点击后，本体选择当前可选项；已有选择时执行反选，并刷新确定按钮及技能自定义回调。
5. 技能继续读取原有 `result.cards` 或 `result.links`，结算流程不变。

## 兼容与错误处理

本设计只使用仓库中已经存在的 noname 事件参数；当前扩展已有多个 `allowChooseAll` 调用，可确认目标运行环境支持该能力。未开启本体配置、联机中的非操作端或不满足本体保护条件时，不显示按钮，原选择流程保持不变。

## 验证

- 检查所有改动点仍保留原选择范围、过滤器、强制状态和 AI。
- 检查“破军”各实现均启用该标记。
- 检查纳入的其他调用均为独立子集选择，没有组合约束。
- 对修改的 JavaScript 文件执行仓库现有的语法或检查命令；若仓库没有专用测试，则至少执行 JavaScript 语法检查和差异审查。
